## Gotchas

- Never delete anything (incl. gitignored dist/) without listing it for approval; rebuild over it instead.
- /auth/me re-reads the account itself, so use a guard-only route to test VersionCache staleness.
- Testcontainers can time out once ("ports not bound in 30 s") when another container is starting; rerun before debugging.
- `pnpm audit`: dev-only findings: sprintf-js (jest/istanbul, moderate), braces 3.0.3 (tailwind cli/shadcn, high, no patched release published yet).
- pnpm 11 asks about install scripts on new deps (`allowBuilds`); esbuild set false and tsup works.
- Traefik routes a container only after it is healthy; until then /api falls through to the web SPA (200 HTML). Smoke waits for the JSON body.
- cors package sends `Access-Control-Allow-Credentials: true` even for disallowed origins (harmless: no ACAO).
- Admin access UI (T18): `src/features/access/` (access.api, access-queries, caller-access = hiding hint derived from own role in GET /roles, permission-matrix.ts = pure editing model, PermissionMatrix/CellDetails/FieldPicker, AccountsPage/InviteDialog/DisableAccountDialog, RolesPage/RolePermissionsPage); constants mirror cms-api in `config/access.constants.ts`. `accessApi` in app services + AccessApiProvider. form-commons dialogs: `Dialog*` (Radix, no corner close, footer has `DialogClose` Cancel); jsdom needs the ResizeObserver stub in test/setup.ts. Roles list `manageable` flag drives assignable roles / editability. Tests: `AccessPages.test.tsx` uses createTestServices + fake handlers keyed "METHOD /path".
- T17a: throttle key source `actor` (account id from req.user.actor; skipped if absent) works only on routes whose class guards include JwtAuthGuard (method-level @Throttle runs after). Policy ACCOUNT_INVITE (IP 20/h + actor 10/h) shared by invite and resend; integration tests use a fresh `signedIn('admin')` per test to get a fresh actor counter. AUTH_INVALID_OTP is HTTP 400.
- T17c: list pagination convention (README "List pagination convention"): `page` default 1, `pageSize` default 20 max 100, `meta {page,pageSize,total}`, strict query (unknown key = 400 ACCESS_INVALID_REQUEST); `pageQuerySchema`/`PageMeta` in access-management.requests.ts, `PAGINATION` constants. Custom role cap 50 (`MAX_CUSTOM_ROLES`, advisory lock in RolesService.create, 409 ROLE_LIMIT_REACHED). UI mirror constants -> T18a.
- cms-api rate limits (T18b): LOGIN_RATE_LIMIT_IP/EMAIL env override rule limits by rule name (config.rateLimit.limitOverrides); set only in docker-compose.smoke.yml.

## T19 API tokens (cms-api)

- Token routes are JWT-only (`requireAccountActor`); another account's token is 404 (not 403); Owner manages all. Subset check = `scopeEntriesBeyondCreator` (no condition comparison, `*` entry needs `*` row); Owner editing checks against the token creator. `ApiTokenGuard` only delegates to `ApiTokenAuthenticator` so consumers just import AccessModule. Tokens are not cached (revoke is immediate); `last_used_at` via raw UPDATE at most 1/min.
- cms-admin (T19): `/api-tokens` UI in `src/features/access`. Raw token only in `TokenFormBody` state (create mutation `gcTime: 0`); the reveal view cannot be dismissed except by its Done button. Token scope grid is content-only (`token-scope.ts`, no conditions; field list kind per action via `scopeFieldListKind`; `*` and delete/publish rows carry no field lists). Expiry is a date input = end of that local day (`token-expiry.ts`). Edit PATCHes only changed fields. Shared `Pagination` lives in PageStates.tsx (takes its copy). UI hint for grantable cells = caller holds the action on the subject or on `*`; non-owner without `roles:read` sees nothing (caller-access limitation, same as accounts).

## T20 Document read API (cms-api)

- Express 5 default query parser is `simple`: `filter[a][gte]=1` is one flat key; the list query is parsed by key (`dto/list-documents.query.ts`), no qs nesting.
- Content reads use `ContentDbProvider.db` (Kysely, own pool, pg `date` -> text). Prisma/migration pools are unchanged.
- Anonymous only when there is no Authorization header; any present-but-invalid credential is 401. Anonymous actor = `AnonymousActorService` (public role, 401 if missing).
- Provisional (T20): `draftAndPublish:false` types ignore `status` for row selection (rows are live, whatever `published_at` is); T21/T22 must store such rows consistently. Filters/sort only on top-level scalar fields + system fields; no `search`; `pageSize` max 100, page max 10000; default sort `-updatedAt`.
- Controllers must not import content.repository/tree-loader (architecture test); DTO files must not either (use `CONTENT_STATUSES` for the status type).

## T21 Document write API (cms-api)

- `documents.command.service.ts`: order = allowlist (`fieldsFor(actor, slug, 'create'|'update').writable`) -> `assertTreeInput` -> `validateTreeValues` (type/required/sanitize; `required` only checked on create or new component items, and only for fields the actor may write) -> txn. OCC = `UPDATE ... SET version = version + 1 WHERE document_id AND status AND version = $v AND update-rowFilter` before `replaceTree`; no row -> select current (404 if hidden) -> 409.
- Decision (T20 provisional resolved): `draftAndPublish:false` types store ONE live row with `published_at` set at create; PUT/DELETE target the `published_at is not null` row. D&P types: create/PUT target the draft (`published_at` null).
- 409 `details` = `{currentVersion, server, submitted, diff}`; `submitted` = sent tree overlaid on the stored doc (new component items have `componentUid: ''` = `NEW_ITEM_UID`); diff is computed on serialized output only (`diff.ts`), paths `values.x` / `components.f[uid].values.x`, `[new#i]`, change added|removed|changed|moved. Actor without read (or read row filter excluding the row): server/submitted null, diff [].
- `version` is stripped in `dto/write-document.body.ts` before the allowlist. Anonymous/reviewer: explicit 403 in the service as well as in PermissionGuard.
- T21 fix round: create permissions take no conditions (validator); success bodies of POST/PUT are `{documentId, version}` unless the actor passes the read row filter + draft check; update rowFilter re-checked after replaceTree (403 rollback); no write throttle in v1 (user).
- T21 follow-up: PolicyEvaluator.grantsFor ignores create rows that carry conditions (fail closed; seeds have none).

## T22 Publish / unpublish / delete (cms-api)

- `publish.service.ts` (`PublishService`): publish = lock draft `FOR UPDATE` -> check `expectedVersion` (409 `details {currentVersion}`) -> delete published row -> `insertTree` of `cloneTree(draft)` (uids kept) -> set published `version` = draft version. Draft is not bumped. Row conditions of the action (publish/unpublish/delete) pick reachable rows (else 404); delete needs ALL rows of the document in scope.
- `draftAndPublish:false`: publish/unpublish = 400 `DOCUMENT_NOT_PUBLISHABLE`; delete removes the live row.
- Activity tracking = port in `src/infrastructure/activity` (`ACTIVITY_RECORDER`, `ActivityModule` binds `NoneActivityRecorder`). Called after commit, failures logged. No `database` adapter yet; create/update emit nothing yet.
- Architecture test allowlist `INTERNAL_COPY_FILES` (publish.service, tree-cloner) may use record loaders without the serializer because they never return records.

## T25 Conflict merge (cms-admin + form-commons)
