# Access (cms-admin)

## Purpose

Admin-side client for accounts, roles, permissions and API tokens, the permission matrix editor, and `useCallerAccess`, which tells other features what the signed-in account may do (hide or disable actions).

## Techniques

Caller access is derived from the account's own role rows in `GET /roles`; the owner holds everything. It is a UI hint only: cms-api enforces every rule.

## Technologies

React 19, TanStack Query, axios (through the shared API client).

## Entry points

`index.ts`: `useCallerAccess`, `isForbidden`, `toAccessError`, `CONTENT_WILDCARD_SUBJECT`, `accessFeature`.

## Where to change what

A new caller check goes on `CallerAccess` in `useCallerAccess.ts` (additive). Keep `Access.constants.ts` in sync with cms-api's access constants.
