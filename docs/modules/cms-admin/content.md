# Content feature (cms-admin)

## Purpose

Everything cms-admin needs to list and edit content documents: the content API client and query keys, the form model, the dynamic form renderer with one adapter per field type, repeatable components, the lazy richtext field and the content menu items per content type.

## Techniques

`FIELD_REGISTRY` maps each field type to an adapter (render, to-form, to-api), so a new type is one entry. `Document.form` converts between the API tree and form values. Components use `useFieldArray` with up/down reorder that keeps focus. Richtext (Tiptap) loads lazily. Masked fields stay masked (`MASKED_VALUE`).

## Technologies

React 19, react-hook-form, TanStack Query, axios (API client), `@abyss/form-commons` (incl. `richtext-input`), `lucide-react`.

## Entry points

`Content.feature.ts` (registered in `features/Features.registry.ts`), `useContentNavItems` (menu), `DynamicFormRenderer`, `createContentApi`.

## Display name

`ContentType.displayName` (from the content-type API) is the only name shown to people: the menu label (`useContentNavItems`), the list page title and table caption, and the new/edit titles. The slug stays in routes and API calls. While the type loads, the title is a `TitleSkeleton`; if it cannot be loaded, the title is `Content`.

## Where to change what

A new field type: one adapter in `Field.registry.tsx` (plus value converters in `FieldValues.rules.ts`). A new content API call: `Content.api.ts` + a key in `Content.queries.ts`.
