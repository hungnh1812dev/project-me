## Gaps

- **G1 (criterion 14, web half).** Nothing renders stored richtext on `apps/web`
  yet (the CV page, T30, is skipped), so "not executed on web" has no test.
  Add a Playwright spec when the public render returns. The public web render
  must sanitize again (handoff follow-up).
- **G2 (criterion 18).** Each event family has its own test, but no single test
  walks the whole D15 list with activity tracking `none`. Activity tracking
  has only the `none` mode today (the `database` adapter is unscheduled), so the
  "even when `none`" condition is the only configuration tested.
- **G3 (criterion 1).** "No HTTP route can create an owner" is proved by
  criterion 2 and the account API tests (the owner role cannot be assigned:
  `accounts-roles.spec.ts` › the owner cannot assign owner (only one owner) and
  nobody manages itself), not by a test that lists every route.
- **G4 (criterion 17).** The 200 branch through Traefik is not asserted on its
  own; the wrong-password 401 proves the request reached the API unredirected.
- **G5 (other, not a §12 item).** Real Cloudinary uploads are not exercised
  (smoke uses a fake provider; the library spec stubs `POST /media`); media
  picker empty / error states are not covered.

## Flaky and quarantined tests

- `media-attach.spec.ts` › uploading in the field attaches the new file; the
  console stayed clean: fixed. The wait for the library list matched a
  response by URL substring and read its body after navigating on, so it could
  catch the wrong response or one whose body was already gone. The list is now
  read inside a route handler on the API route (`<api base>/media`), which
  also supplies the stubbed upload answer.
- `web-session.spec.ts`: independent of `two-factor.spec.ts`. It signs in with
  its own seeded accounts (`E2E_READER_*`, `E2E_READER_2FA_*`) and the owner, and
  imports nothing from the 2FA account state. The smoke stack lifts the login
  limits (`LOGIN_RATE_LIMIT_*`), so spec order no longer spends a shared login
  budget.
- cms-api `password.spec.ts` timing test and one cms-api integration flake: not
  an e2e item, not investigated here (handoff follow-up stays open).
