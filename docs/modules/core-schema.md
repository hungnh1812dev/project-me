# Core schema (Prisma, schema `public`)

Source: `apps/cms-api/prisma/schema.prisma`, migrations in
`apps/cms-api/prisma/migrations/`. Prisma owns only `public`; content tables
(schema `content`, including the registry `content._content_types`) belong
to the content engine (D10). Tables follow SPEC §8.1.

## Commands

| Script                                         | What it does                                                                                                        |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `pnpm --filter @abyss/cms-api db:generate`     | Generate the Prisma client into `src/generated/prisma` (gitignored; turbo runs it before build/lint/typecheck/test) |
| `pnpm --filter @abyss/cms-api db:migrate`      | `prisma migrate deploy`, then the system roles + default permissions seed (needs a build)                           |
| `pnpm --filter @abyss/cms-api db:seed`         | The seed alone (idempotent)                                                                                         |
| `pnpm --filter @abyss/cms-api db:migrate:dev`  | Development only: create a migration from schema changes (`--create-only` to edit it first)                         |
| `pnpm --filter @abyss/cms-api owner:bootstrap` | One-time owner creation (below)                                                                                     |
| `pnpm --filter @abyss/cms-api owner:reset-2fa` | Break-glass: turn 2FA off for one account and end its sessions (below)                                              |

Deploy order: `db:migrate`, then `content:migrate`, then start the API.
In the image (no pnpm): `npm run db:migrate`, `npm run owner:bootstrap`,
`npm run owner:reset-2fa -- --email <address> --yes`.

## Hand-written SQL in the first migration

Prisma generates most of `20261020055626_core_identity`; these parts are
added by hand (Prisma sees no drift from any of them):

- `CREATE EXTENSION citext` for `accounts.email`.
- Ids are `GENERATED BY DEFAULT AS IDENTITY` (SPEC §8.1) instead of `SERIAL`.
- `accounts_single_owner_uq`: unique index on `((1)) WHERE role_slug = 'owner'
AND deleted_at IS NULL` (D1). See ADR 0002 for `role_slug`.
- `roles_rank_ck`: system roles must be exactly the SPEC §6 slug/rank pairs;
  custom roles use ranks 11–39.
- Trigger `roles_protect_system`: slug, rank and `is_system` of a system role
  cannot change, a system role cannot be deleted, a custom role cannot become
  a system role.

## Column decisions (T08)

Where SPEC §8.1 leaves a shape open, the conservative choice:

- **document_id** (UUIDv7, `@default(uuid(7))`, generated by Prisma since
  PG 16 has no `uuidv7()`): on tables addressed through the API: `accounts`,
  `roles`, `api_tokens`, `file_library`.
- **created_by / updated_by** (`ON DELETE SET NULL`): on tables people edit:
  `accounts`, `roles`, `permissions`, `file_library`, `app_settings`.
  `api_tokens.created_by_id` is `NOT NULL ON DELETE CASCADE` (D5). System-
  written tables (`refresh_tokens`, `otp_codes`, `reviewer_sessions`,
  `audit_logs`) have none.
- **audit_logs**: bigint identity, `created_at` only (append-only), no
  `updated_at`.
- **Enums** are PG enums: `account_status`, `two_fa_method`,
  `permission_action`, `otp_purpose`, `media_provider`, `audit_actor_type`.
- **accounts**: `password_hash` nullable (invited accounts set it later);
  `status` defaults to `invited`; `token_version` and
  `roles.policy_version` start at 1; 2FA columns `is_2fa_enabled`,
  `two_fa_method`, `totp_secret_enc` (text, `v1.<iv>.<ct>.<tag>` AES-256-GCM, T13),
  `totp_secret_kid` (key id for `TOTP_ENC_KEY` rotation), `totp_last_step`
  (int, last accepted time step).
- **refresh_tokens**: one row per token (SHA-256 in `token_hash`), grouped
  by `family_id`. A rotation sets `replaced_by_id` to the successor and
  `revoked_at` to the rotation time; that `revoked_at` also anchors the 10 s
  reuse grace window (T11a, `REFRESH_TOKEN_REUSE_GRACE_SECONDS`), so the
  window needs no extra column. Logout and reuse revoke the whole family.
- **permissions**: no unique constraint on (role, subject, action): T14
  allows several rows for the same pair (their fields add up and their
  conditions are ORed, see [access-control.md](access-control.md)). Indexed
  on (role_id, subject).
- **Other text columns** (`ip`, `user_agent`, `subject`, `target_id`) are
  plain `text`; `reviewer_sessions.notes` is `varchar(500)`;
  `file_library.size` is `int` bytes (max upload 100 MB).
- **Content FKs**: `content.<type>.created_by/updated_by` stay without an FK
  to `public.accounts` for now (see the T08 report; revisit in T21 when the
  columns are written).

## System roles seed

`src/modules/identity/system-roles.seed.ts`: inserts `public 0, guest 10,
reviewer 20, editor 30, admin 40, owner 100` with `is_system = true`
(`INSERT ... ON CONFLICT DO NOTHING`), never updates existing rows (names
edited later survive), and fails if a role with a system slug is not that
system role. Safe to run on every deploy.

Then `src/modules/access/role-permissions.seed.ts` inserts the default
permission rows (T14 matrix in [access-control.md](access-control.md)) into
each system role that has **no** rows yet, under an advisory lock. A role the
Owner already configured is never touched.

## owner:bootstrap (D1)

```bash
OWNER_EMAIL=me@example.com pnpm --filter @abyss/cms-api owner:bootstrap
# no terminal (container, CI):
printf '%s\n' "$PASSWORD" | OWNER_EMAIL=me@example.com npm run owner:bootstrap -- --password-stdin
```

- Email from `OWNER_EMAIL`, optional `OWNER_DISPLAY_NAME` (default: the
  email's local part). The password is read from a hidden prompt (typed
  twice) or from stdin with `--password-stdin`, never from argv or env, and
  never printed.
- Password: 12–128 characters. Hash: Argon2id, 64 MiB, t=3, p=4
  (`ARGON2_OPTIONS`).
- One transaction under `pg_advisory_xact_lock`: refuses if a live owner
  exists (`owner.exists`), if the `owner` role is not seeded
  (`owner.role_missing`), or if the email already has an account
  (`owner.email_taken`; accounts are never promoted). Creates an `active`
  owner. The partial unique index backs this up.

## owner:reset-2fa (T13a, break-glass)

**Break-glass tool:** it turns 2FA off for any account, the owner included,
with no password or code. Use it only after confirming the person's identity
out of band.

```bash
pnpm --filter @abyss/cms-api owner:reset-2fa --email someone@example.com
# no terminal (container): --yes is required
npm run owner:reset-2fa -- --email someone@example.com --yes
```

- Prompts `[y/N]` on a terminal; without one, refuses unless `--yes`.
- One transaction on `accounts`: `is_2fa_enabled = false`, `two_fa_method`,
  `totp_secret_enc`, `totp_secret_kid` and `totp_last_step` set to null,
  `token_version + 1`; every live `refresh_tokens` row of the account gets
  `revoked_at`. Code: `src/modules/identity/two-factor-reset.ts`.
- Exit 1 with nothing changed for an unknown or deleted email, or when 2FA
  is already off. Details: cms-api README, "Break-glass 2FA reset".
