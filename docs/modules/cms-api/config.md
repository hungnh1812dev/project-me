# Config (cms-api)

## Purpose

Loads and validates every environment key once at boot and hands the typed `IAppConfig` to the app through `APP_CONFIG`. Boot fails closed on a missing or invalid key; production-only guards (for example the local media provider opt-in) live here.

## Techniques

Zod schemas (`Env.schema.ts`) plus cross-key rules (`ENV_RULES`), small reusable validators; error messages carry paths only, never input values. `summarizeConfig` logs the loaded config with every secret shown only as set/unset; a new field stays out of the log until added on purpose.

## Technologies

NestJS 11 (`ConfigModule`), zod, Node.js `fs` (root certificate for `verify-full` TLS).

## Entry points

`loadAppConfig` / `loadDatabaseConfig` (`AppConfig.setup.ts`), the `APP_CONFIG` token, `ConfigModule`.

## Where to change what

A new env key: add it to `Env.schema.ts` (and a rule in `Env.rules.ts` if it depends on another key), map it in `AppConfig.setup.ts`, add defaults or names to `Config.constants.ts`, add the name to `apps/cms-api/.env.example` and to the summary if it is safe to log. This folder is a tier 3 area (`project.md`).
