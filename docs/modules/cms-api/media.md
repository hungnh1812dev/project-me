# Media (cms-api)

## Purpose

Owns uploaded files: streaming upload with type and size checks, image re-encoding, storage on Cloudinary, local disk (smoke/dev) or a fake (tests), the paged library with search and MIME filters, replace in place, alt text, soft delete with a purge job, and the media and richtext-image references inside content documents (SPEC §15, ADR 0020/0021, D13).

## Techniques

Clean layers: `domain/` rules, `application/` use cases behind ports (`MediaStorage`, `UploadProcessor`, `Repository`), `adapters/`, `http/`. Uploads stream through busboy with per-type limits, `file-type` sniffing and sharp re-encoding. Storage chosen by a factory per provider (`MEDIA_STORAGE_FACTORIES`); each row records its provider. Row locks serialise replace and delete; delete leaves a tombstone, `MediaPurgeJob` removes bytes later and skips rows of another provider. Delete and replace are written to the security audit log. `DocumentMediaService` checks and rewrites media fields and richtext images of a document.

## Technologies

NestJS 11, Prisma 7 + Kysely, busboy, file-type, sharp, Cloudinary SDK, Node.js `fs`/`stream`/`crypto`.

## Entry points

REST `POST/GET /api/v1/media`, `PATCH/DELETE /api/v1/media/:id`, `PUT /api/v1/media/:id/file` (`Media.controller.ts`, rate limits `MEDIA_RATE_LIMIT_POLICIES`); `GET /api/v1/media-files/:fileName` for the local provider; the purge job; `DocumentMediaService` for the documents module.

## Where to change what

A new storage provider: one adapter implementing `MediaStorage` plus an entry in `MEDIA_STORAGE_FACTORIES` and the config enum. A new allowed type or limit: `domain/MediaUpload.rules.ts` (shared with cms-admin via the constants contract). High-risk path: any change gets a security review before commit.
