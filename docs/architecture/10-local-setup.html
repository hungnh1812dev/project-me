First run (empty database)

start:dev never creates tables; migrations are a separate step.

flowchart TB
  a["1. Start Postgres 16"] --> b["2. Write apps/cms-api/.env.local<br/>DB_*, three secrets, ADMIN_ORIGIN, WEB_ORIGIN,<br/>MAIL_PROVIDER=console, MEDIA_PROVIDER=fake, OWNER_SETUP_TOKEN"]
  b --> c["3. Export .env.local into the shell<br/>(migrations do not read it)"]
  c --> d["4. pnpm build (in apps/cms-api)"]
  d --> e["5. pnpm deploy:migrate<br/>check DB_NAME is the database you look at"]
  e --> f["6. pnpm start:dev (cms-api)"]
  f --> g["7. pnpm dev (cms-admin)"]
  g --> h["8. open admin.domain.localhost:5173/setup"]
  h --> i["9. remove OWNER_SETUP_TOKEN, restart cms-api"]
cd apps/cms-api
set -a; source .env.local; set +a     # db:migrate and the CLIs read the shell only
pnpm build                            # the role seed and content:migrate run from dist/
pnpm deploy:migrate                   # db:migrate (Prisma + role seed) then content:migrate
pnpm start:dev
# owner without the web page:
OWNER_EMAIL=you@example.com pnpm owner:bootstrap

Dev stack (agents / tier-2 e2e)

pnpm dev:stack starts Postgres and Mailpit (compose project abyss-dev, docker-compose.dev.yml) and the three dev servers with env from .localEnv.agent; stop with pnpm dev:stack:stop.

SMOKE_KEEP=1 SMOKE_E2E=1 pnpm smoke   # keep it and run Playwright
docker compose -p abyss-smoke down -v # stop a kept stack

Kept stack URLs: http://domain.localhost:8080 and http://admin.domain.localhost:8080. Per-run secrets are generated by scripts/smoke.sh.
