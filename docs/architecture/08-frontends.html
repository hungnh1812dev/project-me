Frontends & packages

How the admin console and the public site are structured, plus the shared UI kit, config package and e2e suite.

cms-admin (React 19 + Vite SPA)

Feature-sliced SPA. Each feature folder exports a FeatureDefinition (routes + nav items) through index.ts and is listed once in features/registry.ts. Session / UI state in Redux Toolkit, server data in TanStack Query, REST through Axios. Served by nginx with its own CSP. Runs on its own origin admin.domain.com so XSS in public content can never run in the admin origin (D14).

Layers: higher may import lower, never the reverse.

flowchart TB
  main["main.tsx"] --> app["app/<br/>composition root: store, providers, shell, routes"]
  app --> feats["features/*<br/>one folder per feature + registry.ts"]
  app --> wiring["features/auth/app-wiring.ts<br/>(only app/ may import it)"]
  feats --> comps["components/"]
  feats --> lib["lib/<br/>api client, feature definition"]
  comps --> cfg["config/<br/>env, endpoints, routes, copy"]
  lib --> cfg
  feats --> fc["@abyss/form-commons"]

Feature order: arrow = may import (through index.ts).

web (Next.js 16 App Router)

Server Components by default; content is read on the server through GraphQL, anonymously, from API_INTERNAL_URL. Browser state with React context + TanStack Query, no Redux. A reader account uses the refresh cookie (same origin domain.com); a reviewer gets a token only. CSP with a fresh nonce per request from proxy.ts.

  app["app/<br/>routes, providers, shell, AccountMenu"] --> feats["features/auth, features/reviewer, features/status"]

  session --> lib["lib/<br/>api client, CSP, alerts"]
  lib --> cfg["config/<br/>env.server, env.client, endpoints"]
