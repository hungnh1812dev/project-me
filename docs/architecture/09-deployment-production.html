CI/CD (GitHub Actions)

App flows never depend on each other. Publish runs only on staging / main when the app image inputs changed and its checks passed. e2e is not a CI gate.

Release order for cms-api

  1. Init container runs npm run deploy:migrate: db:migrate (Prisma migrate deploy + role seed), then content:migrate. Stops at the first failure; idempotent; safe concurrently (Prisma lock, advisory lock).
  2. Main container starts node dist/main.js and runs no migrations.
  3. First install only: set OWNER_SETUP_TOKEN in the Secret, create the owner on https://admin.domain.com/setup, then remove the token and restart.

Secrets and config

Secret keys (at least 32 bytes in production): DB_PASSWORD, JWT_ACCESS_SECRET, OTP_PEPPER, TOTP_ENC_KEY (+ previous key during rotation), SMTP / Cloudinary / Turnstile secrets, OWNER_SETUP_TOKEN (only during setup). Kept encrypted with SOPS in the deploy repo (docs/deployment/k3s-secrets-sops.md). With NODE_ENV=production the API refuses MAIL_PROVIDER=console, MEDIA_PROVIDER=fake, missing or short secrets (D17). Web and admin hold no secrets; VITE_* and NEXT_PUBLIC_* are baked at build time.

Backups

The deploy repo owns a nightly PostgreSQL dump of both schemas and a restore drill: restore into a scratch database, run the migration commands (nothing pending), spot-check, drop. See docs/deployment/k3s-traefik.md §7.
