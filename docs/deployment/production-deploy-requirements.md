# Production deploy requirements

**Scope of this document.** The public API prefix `/api/v1` is unchanged (it is deliberate, kept for future versioning) and the application source is unchanged. Everything below is deploy-side configuration only: versions, proxy and cluster settings, secrets, order of steps. Manifests live in the deploy repo; this page lists what they must contain and links to the contract sections instead of copying them.

Related: `docs/deployment/k3s-traefik.md` (contract and example manifests), `docs/deployment/devops-runbook.md` (who owns what, blockers), `docs/deployment/k3s-secrets-sops.md` (secrets), `docs/deployment/supabase-database.md` (hosted database path).

Placeholders used here: `<domain>`, `<admin-domain>`, `<namespace>`, `<APP_IMAGE_TAG>`, `<pod>`, `<secret values>`. Never write real hosts or secrets into this repo.

## 2. Media-upload-fixes: deploy-side items

Uploads (`POST /api/v1/media`, `PUT /api/v1/media/<id>/file`) can be slow and are rejected early with 401/403/413/415 in some cases. These items make slow uploads succeed and early rejections answer correctly (no 502, no held connection). Full manifests and rationale: `docs/deployment/k3s-traefik.md` section 1 ("Upload timeouts") and section 2.

| Item                           | Where                                                                                                                                                                | Purpose                                                                                                                                    | Expected effect                                                                                                                                                                               |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `websecure` `readTimeout: 5m`  | Traefik entrypoint `transport.respondingTimeouts.readTimeout` (K3s: `HelmChartConfig`; smoke stack: `--entrypoints.web.transport.respondingTimeouts.readTimeout=5m`) | Allow a slow upload body to finish. Applies to every route and also bounds slow request headers.                                           | An upload that takes up to about 5 minutes completes instead of being cut at the Traefik default.                                                                                             |
| Node `requestTimeout` 5 min    | cms-api `Bootstrap.setup.ts` (constant in code, no env key); `headersTimeout` stays at the Node default                                                              | Match the Traefik value so neither side cuts a valid slow upload earlier than the other.                                                   | No cms-api config to set. Do not shorten the Traefik value below it.                                                                                                                          |
| `api-upload` route             | Traefik `IngressRoute`: routes only `POST /api/v1/media` and `PUT /api/v1/media/<id>/file`, priority above the `/api` route, same cms-api service                    | Give uploads their own middleware chain without touching other API routes.                                                                 | Only upload and replace requests get `upload-close`; other `/api` traffic keeps keep-alive.                                                                                                   |
| `upload-close` middleware      | `Middleware` (headers) setting `Connection: close` on the response, attached to `api-upload` only                                                                    | Skip Traefik's drain of up to 256 KB of an unread body when cms-api answers early, so a slow anonymous client cannot hold the answer back. | An early 401/403 is delivered at once and the connection closes. cms-api deliberately does not send this header itself (it would cause a 502).                                                |
| `api-inflight` middleware      | `Middleware` `inFlightReq`, 100 per client IP, on `api-upload` and on the `/api` route (each router counts its own 100)                                              | Bound concurrent slow requests per client, because the 5 minute timeout applies to all `/api` routes including login.                      | One client cannot hold more than 100 simultaneous requests per router; excess get 429. Relies on a correct client IP (next row).                                                              |
| `TRUST_PROXY_HOPS`             | cms-api env, `1` for client -> Traefik -> cms-api (default); `CLIENT_IP_HEADER=cf-connecting-ip` behind Cloudflare                                                   | Make `X-Forwarded-For` parsing return the real client IP for rate limits and `api-inflight`. Never `true`.                                 | Rate limits and logs show real client IPs. Raise only if more proxies append to `X-Forwarded-For`.                                                                                            |
| `externalTrafficPolicy: Local` | Traefik `Service` (K3s `HelmChartConfig` in `kube-system`)                                                                                                           | Without it kube-proxy source-NATs and every client appears as a node IP.                                                                   | One rate-limit and `api-inflight` bucket per real client, not one for everybody. Check: `kubectl -n kube-system get svc traefik -o jsonpath='{.spec.externalTrafficPolicy}'` returns `Local`. |

If the API later moves to its own host, `api-upload` moves with `/api` (`k3s-traefik.md` section 1).

## 3. Deploy order

Details of each step are in the linked sections; this is the order.

1. **Images.** The publish job (`docs/ci-cd.md`, "Publish") pushes `cms-api`, `web` and `cms-admin` to GHCR and bumps `<APP_IMAGE_TAG>` in the deploy repo overlays. Confirm all three tags exist and are the same release. (`k3s-traefik.md` section 1)
2. **Cluster and proxy config (once, then on change).** K3s on the pinned stable version; Traefik `HelmChartConfig` with `externalTrafficPolicy: Local`, the `readTimeout: 5m` entrypoint setting and the `web` -> HTTPS redirect; the `api-inflight` and `upload-close` middlewares and the `api-upload` route next to the `/api` route. (`k3s-traefik.md` sections 1 and 2; the items in section 2 above)
3. **Config and secrets.** ConfigMap `cms-api-config` (include `TRUST_PROXY_HOPS`, `CLIENT_IP_HEADER` if behind Cloudflare), Secrets `cms-api-secrets`, `cms-api-migrate-db`, `postgres-backup`, encrypted with SOPS or sealed-secrets, `<secret values>` never in plain text. Restart pods after any Secret change. (`k3s-traefik.md` sections 3 and 6; `k3s-secrets-sops.md`)
4. **Database and roles.** First install only: run `scripts/db/database-roles.sql` to create `abyss_migrator`, `abyss_api`, `abyss_backup`; then Secrets use `DB_USERNAME=abyss_api` for the API and `abyss_migrator` for migrations. Hosted Supabase: `docs/deployment/supabase-database.md`. (`k3s-traefik.md` section 3, "Database roles (first install)")
5. **Migrations.** Run by the cms-api init container `migrate` with `npm run deploy:migrate` (`db:migrate`, then `content:migrate`). It applies committed migrations only and is safe to re-run. A failed run leaves the pod in `Init:Error` and the old ReplicaSet keeps serving. (`k3s-traefik.md` section 3)
6. **Rollout.** Apply the manifests (Flux reconciles the deploy repo). `RollingUpdate` with `maxSurge: 1`, `maxUnavailable: 0`; one replica per app. First install: create the owner (`OWNER_SETUP_TOKEN` flow). (`k3s-traefik.md` sections 3, 4, 5, 8)

## 4. Post-deploy checks

1. cms-api pod goes `Init:0/1` then `Running`; `kubectl logs <pod> -c migrate` ends with "No pending ..." or the applied list.
2. `curl -fsS https://<domain>/api/v1/health/ready` returns `{"status":"ok"}`.
3. `https://<domain>/` and `https://<admin-domain>/` load; the browser console shows no CSP violations.
4. Sign in as the owner. The Traefik access log shows real client IPs, not node IPs; `externalTrafficPolicy` reads `Local`.
5. Upload a media file larger than a few MB over a throttled link that takes more than 1 minute: it completes (`readTimeout` 5m, Node `requestTimeout`).
6. `POST /api/v1/media` without a session returns 401 (not 502) and the response carries `Connection: close`; a normal `GET /api/v1/...` response does not.
7. The last nightly dump exists off-site and the last restore drill is younger than three months. (`k3s-traefik.md` sections 7 and 9)

## 5. Rollback

- **Image only (no migration in the release):** set `<APP_IMAGE_TAG>` back to the previous tag in the deploy repo and let Flux reconcile; `maxUnavailable: 0` keeps the service up.
- **Release with a migration:** migrations are forward-only. Do not roll the image back across a destructive migration. Destructive changes ship as expand/contract over two releases, so the previous image still runs on the new schema (`k3s-traefik.md` section 3). If data is damaged, restore from the nightly dump using the restore drill (`k3s-traefik.md` section 7).
- **Proxy config (timeouts, `api-upload`, middlewares, `externalTrafficPolicy`):** revert the manifests in the deploy repo. Removing `api-upload` only returns uploads to the `/api` route; without `readTimeout: 5m` slow uploads are cut at the Traefik default.
- **Secrets:** restore the previous encrypted Secret and restart the pod.
