# DataTable

One page of rows with optional sorting, row selection and row actions. Sorting, selection and fetching stay with the parent; the table shows them.

## When to use

- Lists of records people scan, compare, sort or act on in bulk: content entries, users, tokens.
- Use cards or a plain list when there are only one or two fields per item.

## Usage

```tsx
import { DataTable, type DataTableColumn } from '@repo/form-commons/components/forms/DataTable';

const columns: DataTableColumn<Post>[] = [
  {
    key: 'title',
    header: 'Title',
    sortable: true,
    cell: (post) => <a href={post.href}>{post.title}</a>,
  },
  {
    key: 'views',
    header: 'Views',
    sortable: true,
    cellClassName: 'text-right tabular-nums',
    cell: (post) => post.views,
  },
];

<DataTable
  caption="Blog post entries"
  columns={columns}
  rows={page.items}
  rowKey={(post) => post.id}
  rowLabel={(post) => post.title}
  sort={{ orderBy, sortDir, onSortChange }}
  selection={{ selected, onSelectedChange, allLabel: 'Select all entries on this page' }}
  busy={isFetchingNextPage}
  renderActions={(post, label) => <RowMenu post={post} label={label} />}
/>;
```

## Guidelines

**Do**

- Give a `caption` that names the data; it labels the table and its scroll region.
- Make `rowLabel` the human name of the row (the title); checkboxes and actions use it.
- Right-align numbers with `tabular-nums`, and link the first text column to the record.
- Keep `busy` short: the rows fade to 60% opacity, which is below text contrast, so show it only while the next page loads.

**Don't**

- Don't sort or select on the client and the server at once; the table just reports changes.
- Don't put more than one action button per row; use a menu (`renderActions`).

## Accessibility and keyboard

- A captioned `<table>` in a focusable `role="region"`, so it can be scrolled with the keyboard.
- Sortable headers are buttons with `aria-sort`; a new column starts descending, the active one flips.
- Each row checkbox is named `Select <rowLabel>`; the header checkbox is tri-state (`mixed`) and covers this page only.
