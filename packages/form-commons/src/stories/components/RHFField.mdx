# RHFField

`Field` bound to react-hook-form: it renders the label, description, required mark and error, and passes the field's value props to one input through a render prop.

## When to use

- Any input inside a react-hook-form form. It replaces a hand-written `Controller` plus `Field`.
- Outside react-hook-form, use `Field` and pass `value` and `onChange` yourself.

## Usage

```tsx
import { FormProvider, useForm } from 'react-hook-form';

import { RHFField } from '@repo/form-commons/components/rhf/RHFField';
import { Input } from '@repo/form-commons/components/ui/input';
import { Switch } from '@repo/form-commons/components/ui/switch';

type Settings = { title: string; notifications: boolean };

const form = useForm<Settings>({ defaultValues: { title: '', notifications: false } });

<FormProvider {...form}>
  <form noValidate onSubmit={form.handleSubmit(save)}>
    <RHFField<Settings, 'title'> name="title" label="Title" rules={{ required: 'Enter a title.' }}>
      {(field) => <Input {...field} />}
    </RHFField>
    <RHFField<Settings, 'notifications'> name="notifications" label="Notifications">
      {(field) => <Switch {...field} />}
    </RHFField>
  </form>
</FormProvider>;
```

## Validation

Three ways to give a field its rules. They can be mixed; each field shows its first error.

**Native rules**, react-hook-form's own `rules`:

```tsx
<RHFField<Settings, 'title'>
  name="title"
  label="Title"
  rules={{
    required: 'Enter a title.',
    maxLength: { value: 80, message: 'Keep it under 80 characters.' },
  }}
>
  {(field) => <Input {...field} />}
</RHFField>
```

**A schema per field**, with any [Standard Schema](https://standardschema.dev) library (zod 3.24+ and 4, valibot, ArkType, ...). The first issue's message is the error. It runs after `rules`, next to any `rules.validate`, and async schemas are awaited:

```tsx
import { z } from 'zod';

<RHFField<Settings, 'email'>
  name="email"
  label="Email"
  required
  schema={z.email('Enter a valid email address.')}
>
  {(field) => <Input {...field} config={{ type: 'email' }} />}
</RHFField>;
```

`schemaRule(schema)` from `@repo/form-commons/lib/standardSchema` gives the same check as a plain `validate` function, for code that builds `rules` itself.

**One schema for the whole form**, with a resolver from `@hookform/resolvers` (`zodResolver`, `valibotResolver`, `standardSchemaResolver`, ...). `RHFField` needs no `rules` then: it shows whatever error the resolver puts on its path.

```tsx
import { zodResolver } from '@hookform/resolvers/zod';

const schema = z.object({ title: z.string().min(1, 'Enter a title.'), notifications: z.boolean() });
const form = useForm<Settings>({ defaultValues, resolver: zodResolver(schema) });
```

A schema or resolver doesn't set the required mark; pass `required` on fields that must be filled. The package itself doesn't depend on zod or the resolvers: install the ones you use in the app.

## Guidelines

**Do**

- Pass the type parameters (`<Settings, 'title'>`) so `field.value` is typed from the form.
- Spread `field` onto exactly one input; it carries `value`, `onChange`, `onBlur`, `name`, `ref` and `disabled`.
- Put the error message in `rules` ("Enter a title."); it becomes the Field error.
- Use `noValidate` on the form so the browser's own bubbles don't compete with the field errors.

**Don't**

- Don't wrap the input in another `Field`; `RHFField` is the Field.
- Don't set `required` and `rules.required` separately; `required` defaults to `!!rules.required`. With a `schema` or a resolver, do set `required`.
- Don't validate the same rule in a field schema and in the form resolver; pick one place per rule.

## Accessibility and keyboard

- The error is announced (`role="alert"`) and linked to the input with `aria-describedby`; the input gets `aria-invalid`.
- On a failed submit, react-hook-form focuses the first invalid input through `field.ref`.
