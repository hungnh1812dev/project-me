# Input

A single-line text box. `PasswordInput` is the same box with a show/hide toggle.

## When to use

- Short free text: a name, an email, a URL, a number, a search.
- Use a [Textarea](?path=/docs/components-textarea--overview) for more than one line, and a [Select](?path=/docs/components-select--overview) or [RadioGroup](?path=/docs/components-radiogroup--overview) when the answer is one of a known list.
- Use `PasswordInput` for passwords and secrets, so people can check what they typed.

## Usage

```tsx
import { Field } from '@repo/form-commons/components/forms/Field';
import { PasswordInput } from '@repo/form-commons/components/forms/PasswordInput';
import { Input } from '@repo/form-commons/components/ui/input';

<Field label="Email" description="We send the invite here.">
  <Input value={email} onChange={setEmail} config={{ type: 'email', autoComplete: 'email' }} />
</Field>

<Field label="Password">
  <PasswordInput value={password} onChange={setPassword} config={{ autoComplete: 'new-password' }} />
</Field>
```

`config` takes the JSON-only native options (`type`, `placeholder`, `maxLength`, `inputMode`, `autoComplete`, ...). Icons and buttons go in the `leading` and `trailing` slots, which aren't JSON.

## Guidelines

**Do**

- Always give a visible label through `Field`. A placeholder is an example, not a label.
- Set `type`, `inputMode` and `autoComplete` so phones show the right keyboard and browsers can fill it.
- Write errors that say how to fix it ("Enter a valid email address."), and pass them to `Field`'s `error`.
- Use `description` for format hints that must stay visible while typing.

**Don't**

- Don't use `disabled` to show a value the user may read but not change: use `readOnly`, which stays focusable and readable.
- Don't validate on every keystroke before the first blur; it shouts at people mid-word.
- Don't put essential instructions in the placeholder; it disappears on typing.

## Accessibility and keyboard

- `Field` connects the label (`htmlFor`), the description and the error (`aria-describedby`), and sets `aria-invalid` and `aria-required`.
- `PasswordInput`'s toggle is a button named "Show password" / "Hide password" with `aria-pressed`; it keeps the value.
- Native text editing keys work as usual; nothing is trapped.
