# JsonInput

A JSON code editor (CodeMirror 6) with syntax highlighting, line numbers, validation and a "Format JSON" button. It loads lazily.

## When to use

- Admin forms that edit raw JSON: metadata, settings, a schema.
- Prefer dedicated controls when the JSON has a known shape that people edit often; JSON is for the open-ended rest.

## Usage

```tsx
import { Field } from '@repo/form-commons/components/forms/Field';
import { JsonInput } from '@repo/form-commons/components/forms/JsonInput';

const [text, setText] = useState('');
const [error, setError] = useState<string | null>(null);

<Field label="Metadata" description="A JSON object." error={error}>
  <JsonInput
    value={text}
    onChange={setText}
    onValidate={setError}
    config={{ label: 'Metadata', expect: 'object', rows: 6 }}
  />
</Field>;
```

The value is the text. `onValidate` gets the parse message (or `null`), and `onValueChange` the parsed value. In react-hook-form, bind it with [RHFField](?path=/docs/components-rhffield--overview) and a `rules.validate` built on `parseJson`.

## Guidelines

**Do**

- Set `config.label` to the Field label: it names the editor inside its shadow root.
- Use `expect: 'object'` or `'array'` when the shape is fixed, so the message says what is wrong.
- Show `onValidate`'s message as the Field `error`.

**Don't**

- Don't use it for long prose or code that isn't JSON.
- Don't expect the editor to ignore edits: it keeps its own document, so a parent that drops an `onChange` still shows the typed text until it sets a new `value`.

## Accessibility and keyboard

- The editor is a `role="textbox"` named by `config.label`, with `aria-invalid`, `aria-required` and `aria-readonly`; clicking the Field label focuses it.
- **Tab** and **Shift+Tab** leave the editor (there is no Tab-to-indent), so it is not a keyboard trap.
- Validation runs after the first blur, then on every change.
