# Conventions (read on demand)

Cross-cutting facts only. Never read a conventions file whole: grep the section you need (e.g. `grep -n -A3 -i prisma .agent-state/conventions*.md`).
App-specific facts: `conventions-backend.md` (apps/cms-api), `conventions-frontend.md` (apps/cms-admin, apps/web, packages/form-commons). Module structure and API details: the module's README / `docs/modules/*.md`. Finished-task history: `tasks/done.md` and git log.

## Tooling
- Node 24.18 (`.nvmrc` = 24), pnpm 11.5.2, turbo 2.11.9. Root: `pnpm build|test|lint|typecheck` (turbo), `pnpm format` / `format:check`.
- TypeScript 6.0.3 per project (ADR 0001). NestJS pinned 11.2.7. Prisma 7.10.1 pinned (ignore the 8.0 rc). Kysely pinned 0.28.x (0.29+ is ESM-only and breaks the CJS build/ts-jest). graphql pinned 17.0.2.
- pnpm 11 minimumReleaseAge (1 day): pin versions released more than 1 day ago, else it writes `minimumReleaseAgeExclude` into pnpm-workspace.yaml. Stale lock entries: `pnpm clean --lockfile && pnpm install`. Lockfile is root pnpm-lock.yaml.
- `allowBuilds` in pnpm-workspace.yaml: install scripts default off; add new ones explicitly (`@prisma/engines`/`prisma` true, `argon2`/`esbuild` false).
- Per-project tooling: own tsconfig extending `../../tsconfig.base.json`, `eslint.config.mjs` and `oxlint.config.ts` from `@abyss/base-config` (base + local extend, D2), `.prettierrc.cjs` from `@abyss/base-config`. `@abyss/base-config` is built to `dist/` (D3, ESM, exports `types`/`import`/`default`): run `pnpm --filter @abyss/base-config build` once after a fresh clone, and before any editor ESLint/Prettier extension use. `lint` = `oxlint && eslint .`, exact-pinned devDeps; add the folder to `abyss.code-workspace`. tsconfig.base has `declaration: true`: set false in noEmit projects.
- Oxlint (1.88): only one of `.oxlintrc.json` / `oxlint.config.ts` per directory; `extends: [baseOxlint]` does not carry `plugins`, so set them per project; `oxlint.config.ts` is ignored by ESLint (base ignore). Config TS files load via Node type stripping (workspace symlink, not node_modules).
- `.prettierignore` skips `.claude/`, `SPEC.md`, `tasks/`, `CMS_*.html`, lockfile, `.next/`, `next-env.d.ts`. Leave `scripts/*.sh` out of prettier (no parser).
- Pre-commit hook (ADR 0018): husky + lint-staged run `pnpm format:staged` on staged files; agents never skip it with `--no-verify` / `HUSKY=0`.
- a11y lint runs via oxlint `jsx-a11y` (eslint-plugin-jsx-a11y does not support ESLint 10). oxlint forbids conditional expect; prefers `<output>` over `role="status"`; copy keys must not start with `use` (react-hooks false positive).

## Testing & smoke
- `pnpm smoke` = scripts/smoke.sh (compose project `abyss-smoke`, port 8080, `SMOKE_KEEP=1` keeps the stack for browser checks; teardown `docker compose -p abyss-smoke down -v`). New cms-api env keys go into docker-compose.smoke.yml `cms-api.environment` (secrets generated in smoke.sh as SMOKE_*); new assertions use `request`/`expect_status`/`expect_header` and go into the matching `scripts/smoke/<group>.sh` (`check_<group>()`, called from smoke.sh in order).
- Tier 2: `pnpm dev:stack` (Postgres + Mailpit from ready images as project `abyss-dev`, apps in dev mode, ~30 s; env only from `.localEnv.agent`, state in gitignored `.dev-stack/`), then `E2E_STACK=dev pnpm e2e:spec <spec>` (needed when a `.smoke/e2e-vars.sh` also exists); stop with `pnpm dev:stack:stop`. Never touches `abyss-smoke`.
- Iterate e2e with `pnpm e2e:spec <spec>` against a running stack (tier 3: `SMOKE_KEEP=1` writes the gitignored `.smoke/e2e-vars.sh`). Checklist tier 3 (ADR 0022): a phase checkpoint runs a scoped run (`SMOKE_KEEP=1 pnpm smoke`, then `E2E_STACK=smoke pnpm e2e:spec` on the test scope); the final run is `SMOKE_KEEP=1 SMOKE_E2E=1 pnpm smoke`, once, in the final session; re-test rounds follow `test-tiers` "Tier 3 re-test rounds" (ADR 0021): `test-only` → `E2E_STACK=smoke pnpm e2e:spec <retry set>` on the kept stack; `app` and `stack` → a fresh full run (no in-place rebuild until ADR 0021 decision 5). Specs share the stack's data and rate-limit counters between runs.
- e2e: `apps/e2e` (Playwright, Chromium in node_modules via `browsers:install`), run on the stack of the unit's tier; `workers: 1`. Rate-limit budget: owner login 4 of 5 per 15 min, request-otp 4 of 5 per IP across smoke + e2e: keep new specs within it. Seeded accounts: e2e-2fa, reader guests (E2E_READER_*, E2E_READER_2FA_*). Mailpit at mail.<SMOKE_DOMAIN>.
- Manual DevTools checks on a kept smoke stack: the owner password is never printed; set a known one (argon2 hash via `node -e` in the cms-api container, psql update in the db container) - only in the abyss-smoke stack.
- Component preview without an app: render with react-dom/server into scratchpad HTML + dist/styles.css, open via chrome-devtools MCP.
- CI has no e2e job (user decision, T37g): e2e runs locally only (`pnpm smoke`, `pnpm e2e:spec`). CI checks and publish run from `.github/`. Static cms-api env is `scripts/stack/cms-api.env` (add new static cms-api settings there, not in the compose file). Lint workflows: `docker run --rm -v "$PWD":/repo -w /repo rhysd/actionlint:latest`.

## User decisions in force
- Prettier defaults + singleQuote. cms-admin look D23 (premium theme; web keeps palette A), system font stack, no dark mode in v1, Button default variant secondary, dialog/form buttons secondary left, primary right, end-aligned, destructive apart at the left end (ADM-6).
- Env names are approved per task; names only in `.env.example`, values always from the user. Production secrets/keys (Cloudinary, Turnstile, SMTP) come from the user.
- Smoke-only overrides (rate limits, Turnstile test keys, Cloudinary dummies) live only in docker-compose.smoke.yml / the smoke build, never in production config.
- Shared smoke stack: one agent runs `pnpm smoke` at a time; no docker teardown without the manager's word; never touch any other docker stack.
- Sensitive fields (Q5): reference.phone, company (root + experience), github, email.
- Web: reader-only session sharing (privileged = any `/auth/me` permission whose action is not `read`); refused privileged sign-in calls logout best-effort. GraphQL: queries + document reads only, introspection off in production, limits in `GRAPHQL_LIMITS`.
- No write throttle in v1. Activity tracking = port with `none` adapter until the `database` adapter is scheduled.
- Owner creation (OS, ADR 0005): one-time `/setup` page, open only while no owner exists, guarded by a setup token from a k8s secret; after setup go to the login page (no direct sign-in). `owner:bootstrap` CLI stays as a fallback. displayName max 100 characters (setup route and CLI).
- Deploy (T37): one cms-api image, run as init (`deploy:migrate` = `db:migrate` then `content:migrate`, committed migrations only; CI fails on a missing migration via `content:generate --check`) and as main. docker-compose is for local testing only.
- CI (T37): triggers keep the template's branches (develop/staging/main), but never assume staging/develop exist. Actions are pinned to commit SHAs. Publish waits only for the app checks (not e2e, not the repo job). Agents never push.
- Backups (user, 2026-10-27): opt-in. The feature runs only when the `BACKUP_STORAGE_*` keys are set; unset means both endpoints answer 404 `BACKUPS_NOT_CONFIGURED`; the owner still sees the menu item and the page loads the status on demand (Check button). No separate enable flag (ADR 0013).
- Backups checks (2026-11-10, user, feature backup, checkpoint BK-C): the download check runs with the backups API mocked plus cms-api adapter and config tests; a real-bucket download is launch gate LG-3. CBKC-12 (429 no-store) is accepted on the filter code and unit spec, with no live owner-token run. CBKC-13 is accepted on tier-1 evidence (CBKC-3, CBKC-7). CBKC-15 is accepted on Playwright coverage (375/1280 px, no console or CSP errors), without a DevTools visual review. CBKC-16's editor refusal is accepted on the CBKC-3 integration test, without a seeded editor on the stack.
- Git (2026-10-28): never commit anything under `tasks/`; `.agent-state/` is tracked (309ef43).
- Launch (2026-10-27): no public DNS, ingress or announced URL until phase LG passes and the user approves in writing. Reviewer features ship OFF in production (`REVIEWER_FEATURE_ENABLED=false`, `WEB_STATUS_PAGE_ENABLED=false`); ON in dev, demo and smoke stacks (ADR 0014).
- LICENSE (2026-11-04, user decision): `AGPL-3.0-only`, the official text unmodified (never edit `LICENSE`); holder AbyssOfTime Dev; `NOTICE` holds the copyright lines and the owner's non-binding request to be told about use; root package.json license `AGPL-3.0-only`. A rule that makes notification mandatory would make the project non-open-source: ask the user first.
- Database (2026-10-27, ADR 0012): Supabase Session pooler on 5432 only (never 6543, no direct connection), TLS `verify-full`, runtime role `abyss_api`, backup role `abyss_backup`, migrations as the DDL-capable migrator role; free-plan pause accepted for launch.
- Media (2026-10-31/11-01, SPEC §15, ADR 0020): a file shows `fileName` + 8 hex of its sha256; replace in place keeps the id (`PUT /media/:id/file`) and takes the new file name; the old public URL stays served until the purge; upload limits per kind: image 10 MB, PDF 20 MB, video 100 MB; PDF cards have no "View original" link.
- Local media provider (ADR 0021): under `NODE_ENV=production` only with `ALLOW_LOCAL_MEDIA_PROVIDER=smoke` (smoke stack env only); the fake provider stays refused; no per-IP throttle on `GET /media-files/:fileName` while local is smoke/dev only; the purge skips and logs rows whose provider differs from the active storage.
- Richtext images (D13): images are media references; the web sanitizer keeps an `img` only with the exact configured origin (scheme and port included) and a valid `data-media-id`; no Cloudinary path check; a local http origin is allowed for smoke/dev.
- Check credentials (2026-11-01): qc may read only `E2E_OWNER_PASSWORD` from `.dev-stack/e2e-vars.sh` and `.smoke/e2e-vars.sh`; qc and security-qc share owner credentials through `.localEnv.agent` (noted changes, never printed); the manager never reads its values; limited-role accounts for checks are created by qc on the dev stack only.
- Remember me (2026-11-06, user, feature remember-me): a ticked "Keep me signed in" keeps the sign-in 30 days (sliding); unticked is a session cookie that ends with the browser session or 12 h after last use; no sign-out on tab close; existing sessions get 30 days at their next rotation; ADR 0018 says "the remembered mode (D22)".
- Draft-publish (2026-11-02, no SPEC section; `features/draft-publish/SUMMARY.md`, flow `content-editing`): `publishState` is derived from the two rows (never stored), only for readers who may read drafts, not in GraphQL; unpublish returns to draft; every save bumps the version; discard needs update plus write access to every root field, no bulk discard; Publish is disabled until saved and Save is disabled until a document's form changes; displayName is required, 1-60 code points; Unpublish uses `warning`, Discard `destructive`.
- Reviewer-toggle dropped (2026-11-02): its SEC-1 checks run at launch gate LG-D.
- Test accounts (2026-11-07, user): every test account's info (email, password, etc.) is generated once, stored in `.localEnv.agent` (noted), and reused afterwards; if the stored one exists, reuse it; if the account in use differs from the stored one, sync the account in use to the stored one where possible. Values are never printed in reports; the manager never reads them.
- 2FA manage limit (2026-11-07, user, stack-accounts finding SA-A-qc#1): the 2FA setup/enable/disable limit (5 per 15 min per IP) has a test-stack-only override `TWO_FACTOR_MANAGE_RATE_LIMIT_IP` (raised on smoke and dev stacks); production stays at 5.
- Invite and OTP-cap limits (2026-11-09, web-content-api feature-qc#1): test-stack-only overrides `ACCOUNT_INVITE_RATE_LIMIT_IP`, `ACCOUNT_INVITE_RATE_LIMIT_ACTOR` (per hour) and `OTP_ISSUE_RATE_LIMIT_ACCOUNT` (codes per account per hour, read by OtpService), `PASSWORD_SUBMIT_RATE_LIMIT_IP`, `PASSWORD_CHANGE_RATE_LIMIT_IP` (per 15 min) are raised on smoke and dev stacks; production keeps 20 / 10 / 5.
- Security checks on the dev database (2026-11-07, user): security-qc may run read-only `psql` or `docker exec` against the dev database to read rows (e.g. refresh_tokens); no writes.
- DevOps web deploy doc (2026-11-08, user): no new feature; the doc `docs/deployments/web.md` is a one-off exception that runs without a feature folder (no `current.md`, no board). core-builder writes only that doc, `devops-runbook.md` link and a `CHANGELOG.md` Unreleased line; the commit still asks the user first.
- Request duration log (2026-11-07, user, feature request-timing-log, API-1): cms-api writes one info line per finished request (method, path without query, status, duration ms), warn above 1000 ms; all requests except health probes; no request id; aborted requests are not logged.

- Web API token scope (2026-11-08, user, feature web-content-api, Q-WCT1): the web API token keeps scope `*` read on dev, smoke and production; not narrowed to a type list; D5 and the read-only guest creator bound it.
- Anonymous CV on refetch failure (2026-11-09, user, feature web-content-api, DR1): when a CV refetch fails, the page keeps showing the anonymous CV rather than an error.
- Local-env access (2026-11-12, user, feature schema-builder, CSCB-B-20): qc and security-qc have full access to `.localEnv.agent` (read and write, values never printed in reports); this replaces the narrower "Check credentials" rule above for that file. The matching permission rule in `.claude/settings.local.json` is still pending the user's exact pattern. Account reuse per "Test accounts" above.
- Smoke scope (2026-11-12, user, ADR 0022): tier 3 runs only the modules a feature touches or can affect, at each phase checkpoint; the full smoke suite runs only once, in the final session, after every final checklist row passes. Answers: (1) each spec gets a flow tag, with a contract test; (2) after a failed final run, only the failed specs and the fix scope re-run; (3) existing "Full e2e suite green" rows run as scoped (note `scoped per ADR 0022`), the final-run row is added at the end; (4) the test scope is measured from the feature base.
- No final run (2026-11-12, user, ADR 0022 amendment): when every phase checkpoint passed tier 3, the feature checks carry those results and run no tier 3 and no full suite; the full suite runs only when the user asks.

## Gotchas
- base-config `abyss/file-names` is opt-in: `baseEslint({ fileNames: {...} })` (options in packages/base-config/README.md); lint paths are relative to the lint cwd, so it only checks `src`, `test`, `tests` by default. Rebuild base-config (`build`) before a consumer lints.
- In zsh, `$VAR` holding several docker args is NOT word-split: pass args explicitly.
- Traefik routes a container only after it is healthy; until then /api falls through to the web (200 HTML). Smoke waits for the JSON body.
- cors sends `Access-Control-Allow-Credentials: true` even for disallowed origins (harmless: no ACAO).
- `pnpm audit` known dev-only findings: sprintf-js (moderate), braces 3.0.3 (high, no patched release).
- CI: `.github/scripts/affected.test.sh` must pass after any change to `affected.sh` or workflow routing; no CI file may reference docker compose (`grep -rn compose .github`).
- Publish: Environment build args (VITE_API_BASE_URL, NEXT_PUBLIC_*) are read in `_publish.yml` image job via `vars`, never secrets; admin bundle check takes the full API base URL (`.github/scripts/bundle-check.sh <image> <url>`).
