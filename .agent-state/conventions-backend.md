# Conventions - backend (read on demand)

apps/cms-api. grep the section you need; cross-cutting facts are in `conventions.md`.

## Testing
- cms-api Jest projects `unit` (src/**/*.spec.ts) + `integration` (test/integration, Testcontainers `postgres:17-alpine`, Docker must run). Jest needs `NODE_OPTIONS=--experimental-vm-modules` (set in scripts). One shared container per run (jest globalSetup); `startPostgres()` gives each file its own database on it, never start a container in a spec. The OTP timing-ratio test in password.spec.ts can flake under load: rerun before debugging. Run unit tests with `pnpm --filter @abyss/cms-api test:unit`, never bare `jest` (it lacks the ESM flag).
- `createTestApp(env, overrides, testModules)` in `test/fixtures/TestApp.fixture.ts` shares the real pipeline; `Clock` is the only time source (tests spyOn `app.get(Clock).now`). Test DB env: `dbEnvOf(url)` / `TEST_DB_ENV` in test/fixtures/env.fixture.ts.
- S3 stand-in for the backups adapter spec: `chrislusf/seaweedfs:4.51` via `GenericContainer` inside that one spec (MinIO is gone from Docker Hub); run one integration file with `jest --selectProjects integration --testPathPatterns <name>` under the NODE_OPTIONS above.
- In Jest, fs errors and plain objects from other realms fail `instanceof` / plain-object checks: check structurally (`error.code`).
- eslint flags `expect.stringContaining` inside object literals (unsafe any): wrap in a helper returning `unknown`.
- Role-privilege integration tests: roles are server-wide on the shared Testcontainers server, so use `randomRoleName` and drop them after the database (`dropRoles`); `applyDatabaseRoles` in `CoreDb.fixture.ts` runs `scripts/db/database-roles.sql` through `pg` (no psql in tests), so keep that script free of meta-commands other than line-start `\if :{?x}` / `\set` defaults. Never assert on global catalogs (e.g. all `pg_read_all_data` members); filter by the suite's role.
- Supertest: compute the bearer token before calling `http()`; an `await` between `http()` and `.end` closes the ephemeral server ("reading 'address'").
- cms-api integration specs that create reviewer sessions must boot with `REVIEWER_FEATURE_ENABLED: 'true'` (default is off, ADR 0014). Local PG* shell vars (PGHOST, PGSSLMODE...) break Testcontainers runs: unset them first.

## Backend
- Transactions: new multi-write flows use `CORE_TRANSACTION_RUNNER` (`infrastructure/database/TransactionRunner.port.ts`); cache drops go in `unit.afterCommit`. `prismaTxOf(unit)` is for repositories only; there is no way to wrap a borrowed tx (CR-cl-1).
- Errors: read a thrown value only through `describeError` (`common/http/DescribeHttpException.rules.ts`); never `instanceof HttpException` outside `common/`. `DomainError` (`common/errors/`) maps via `DOMAIN_ERROR_HTTP_STATUS`; no module throws it until its CR task.
- Errors: throw HttpException with `{ errorCode, message }`; the filter passes `details` for 4xx. Constants in `src/common/constants/*.constants.ts`; config via `APP_CONFIG` (src/config).
- DB TLS: Prisma's schema engine ignores `sslmode=verify-full`/`sslrootcert` (unverified); verified TLS there is `sslmode=require&sslcert=<CA>&sslaccept=strict` (prisma.config.ts). Re-test on a Prisma upgrade.
- Config log: `config/ConfigSummary.rules.ts` lists every logged field by hand; a new config field or env key needs a line there, a sentinel entry if secret (`ConfigSummary.rules.spec.ts`), and a `.env.example` entry (parity spec; CLI-only keys go on its allowlist).
- Content SQL names come only from `naming.ts` `planTables()`. Content reads go through `ContentDbProvider.db` (Kysely); controllers and DTOs must not import KyselyContent.repository/TreeLoader.adapter (architecture tests).
- Architecture specs use `test/architecture/ImportGraph.analyzer.ts` (resolved files, facades followed), never path-string regexes.
- Architecture specs read module file paths only from `test/architecture/SourcePaths.constants.ts` (also owns `SRC_ROOT`) and call `assertPinnedPathsExist` ("missing path" on a stale entry); a moved file is one edit there (static `import`s of module symbols still change in the spec). `layerOfFile` (module-graph.ts) gives the ADR 0006 layer; `ResolvedImport.isTypeOnly` and `textMatches` live in import-graph.ts.
- Layer rules (ADR 0006 §2) live in `test/architecture/LayerRules.constants.ts` (`LAYER_RULES`, `KNOWN_LAYER_VIOLATIONS` (empty), `LAYER_EXCEPTIONS`); `LayerCheck.analyzer.ts` runs them on every folder under `modules/` (no module list; a sub-folder not yet moved goes in `UNMIGRATED_FOLDERS` with its removing task); the layer guard reads `import { type X }` as a value import, so write type-only imports as `import type`; moving the access field projection means editing `source-paths.constants.ts` only.
- Every record body goes through `RecordSerializer` with `recordReadAccess(actor, fieldsFor().readable)`; writes: strip `version`, then `WriteAllowlist.apply`, then `assertTreeInput`. Rules: docs/modules/access-control.md.
- Token-accepting content routes: `@UseGuards(ApiTokenGuard, PermissionGuard)` (module imports AccessModule).
- Scale-out: VersionCache, rate-limit store, TwoFactorChallengeStore and presence are in-memory (one replica only).
- After any `content/schemas` change, rerun `graphql:print-schema` (SDL `content/schema.graphql` is generated).

- Identity constants: `identity/domain/Identity.constants.ts` (TTLs, codes, messages, OtpPurpose, TwoFaMethod), cookie/origin/strategy name in `identity/http/IdentityHttp.constants.ts`; DomainError constructors in `domain/Identity.errors.ts` (used by all identity use cases). Identity use cases (Auth, Password, TwoFactor*, SessionRevocation) are in `application/`; `hashPassword`/`verifyPassword` are exported from `application/Password.service.ts`, `buildOtpMail` from `application/Otp.service.ts`. Identity ports in `application/Identity.port.ts` (AccountRepository also serves owner setup, reset-2fa and seed), Prisma adapters in `identity/adapters/`; HTTP routes, rate limits, cookie and `Jwt.strategy.ts` are in `identity/http/` (`IdentityHttp.constants.ts`); the CLIs are `cli/*.command.ts` and build their use cases through `cli/IdentityCli.setup.ts` (`identityUseCasesOf(prisma)` also serves integration specs; `seed:account` use case is `application/SeedAccount.service.ts`, reachable only from `cli/`); refresh-token and OTP times come from `Clock`, so an integration spec that spies `Clock.now` with a jumping value must read real time for grace-window tests.
- Documents constants: `documents/domain/Documents.constants.ts` (rules, limits, messages), `http/DocumentsHttp.constants.ts` (URL and body keys, derived from domain `LIST_QUERY_PARTS`), `adapters/DocumentsSql.constants.ts`. A domain refusal is `DomainError`; read it with `describeError`, never `instanceof BadRequestException`. Documents builds its refusals in `documents/domain/Documents.errors.ts`; `application/` uses `Clock` and `AppLogger`, no Nest exceptions.
- cms-api: every module under `src/modules/` is imported only through its `index.ts` (lint-enforced in `apps/cms-api/eslint.config.mjs`; `access/management` has its own). Exceptions kept out of facades: `access/field-projection`, `access/document-auth`, `content-engine/adapters/KyselyContent.repository`, `content-engine/adapters/TreeLoader.adapter`. Never export loaders or raw audit writers from a facade.
- A mirrored cms-api constant changes in `*.constants.ts`; then run `pnpm --filter @abyss/cms-api contract:print` and commit `content/public-constants.json` (CI runs `-- --check`). Client tests import the JSON; production code never does.
- content-engine is layered: `domain/` pure code, `application/` ports + `ContentRegistry`, `adapters/` Kysely/pg/fs. Content repository methods take a `UnitOfWork` (specs seed rows with `inContentUnit(db, work)` from `test/fixtures/content-unit.fixture.ts`). `domain/` holds the pure code; tests that read `content/schemas/cv-page.json` use four `..` from `domain/`.
- Prettier: never run it on a whole `src/` folder (it reformatted an unrelated file once); pass the changed paths.

- Recurring in-process jobs: `jobs/<Name>.job.ts` starts `startIntervalJob` (`src/infrastructure/scheduling/IntervalJob.adapter.ts`) and calls an application service (media purge, reviewer cleanup).
- Reviewer: the Turnstile verifier is bound in `Reviewer.module.ts` (port `TURNSTILE_VERIFIER` in `application/Reviewer.port.ts`; tests override that token); `token_version` writes sit in `adapters/PrismaReviewerAccount.adapter.ts` (`REVIEWER_ACCOUNT_ADAPTER_FILE`, session-ownership allowlist).
- Row filters (`RowCondition`) are Kysely expressions: a repository applies them on the content handle (`ContentDbProvider`), listed in `LAYER_EXCEPTIONS` (documents, media).
- System permission subjects used by more than one module (`MEDIA_SUBJECT`, `REVIEWER_SETTINGS_SUBJECT`) are exported from the access facade; a controller exports its `*_RATE_LIMIT_POLICIES` for the rate-limit architecture spec.

- Fields marked `sensitive: true` are masked for the `public`/`reviewer` roles unless a type-specific read row lists them (`SENSITIVE_MASKED_ROLE_SLUGS`, `PolicyEvaluator.fieldsFor`); new sensitive flags need a `content:generate` migration (hash only).
- cms-api: unit conversions come only from `common/constants/Time.constants.ts`; a literal 1000 in another `*.constants.ts` fails eslint (R2-15).
